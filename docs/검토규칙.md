# 검토 규칙 — 청파중앙교회 홈페이지 (welcome_home)

> `/harness:review`의 기준 축 검토자(`harness:reviewer`)가 이 파일만 보고 판정한다. 해설 없이 규칙만 쓴다. 규칙마다 출처(설계서 · 인계의 절)를 괄호로 단다. 지어낸 규칙을 넣지 않는다.

## 규칙

### 디자인 시스템
① UI에 이모지·유니코드 아이콘 심볼(☀🌙🙏📍▶★♥ 등)을 쓰지 않는다. 아이콘은 Lucide React 또는 최소한의 커스텀 선형 SVG만. Font Awesome 금지 (출처: CLAUDE.md · 디자인 원칙 1, 아이콘 규칙 / qa.md · 1)
② AI 생성 이미지·아이콘, 스톡 이미지(unsplash.com 하드코딩 포함)를 쓰지 않는다. 실제 교회 사진이 없으면 `ImagePlaceholder` (출처: CLAUDE.md · 디자인 원칙 2 / qa.md · 1)
③ 색은 브랜드 토큰(`--color-primary` #2B3A8C 남색 · `--color-secondary` #6EC6E6 하늘색 · `--color-accent` #D4A843 골드 등)만 쓴다. 골드는 표어 라벨·특별 강조에만. 토큰 값을 바꾸지 않는다 (출처: CLAUDE.md · 브랜드 컬러 / HANDOFF.md · 디자인 시스템(변경 금지))
④ 폰트는 제목 Noto Serif KR, 본문 Pretendard. Inter · Roboto · Arial · system-ui 금지 (출처: CLAUDE.md · 타이포그래피 / qa.md · 1)
⑤ 이미지는 `next/image`를 쓴다 (출처: CLAUDE.md · 품질 기준)
⑥ UI 텍스트는 한국어 (출처: CLAUDE.md · 핵심 규칙 4)
⑦ 시맨틱 HTML · aria-label · alt · 키보드 내비게이션. 문서에 `<main>`은 하나 (출처: CLAUDE.md · 품질 기준 / HANDOFF.md · S7-4)

### 도메인 · URL
⑧ 사이트 URL을 하드코딩하지 않는다. canonical · OG · sitemap · robots는 `src/lib/site.ts`의 `SITE_URL`만 쓴다 (출처: HANDOFF.md · S1)
⑨ DNS 전환 전에 `NEXT_PUBLIC_SITE_URL`을 등록하지 않는다. `chungpa21.org`를 Vercel에 연동하지 않는다 (출처: HANDOFF.md · 도메인 연동 금지)
⑩ 각 페이지는 자기 경로의 canonical을 선언한다. 루트 `layout.tsx`에 canonical을 두지 않는다 (출처: HANDOFF.md · S1-b)
⑪ sitemap에는 실재하는 경로만 (출처: HANDOFF.md · S1)

### 렌더링 (S7 교훈)
⑫ `globals.css`의 요소 선택자 규칙은 반드시 `@layer base` 안에 둔다 (출처: HANDOFF.md · S7-1)
⑬ 화면 최상단 콘텐츠(표어·CTA)의 기본 상태는 「보임」. 등장 효과만 얹는다 — JS가 실패해도 보여야 한다 (출처: HANDOFF.md · S7-2 원칙)
⑭ framer-motion을 다시 들이지 않는다. 애니메이션은 CSS (출처: HANDOFF.md · S7-2)
⑮ 어두운/투명 배경 로고는 `logo-mark.png`(투명)를 쓴다. 원본 `logo.png`(검정 배경 JPEG)에 invert 필터를 걸지 않는다 (출처: HANDOFF.md · S7-3)
⑯ 화면이 바뀌는 변경은 실제 브라우저로 열어 확인한 기록이 있어야 한다 (출처: HANDOFF.md · S7 배운 것)

### 운영
⑰ 새 코드에 Sanity 의존(`sanity` · `next-sanity` · `@sanity/client` · GROQ)을 더하지 않는다. 콘텐츠는 저장소 `content/` 파일, 홈페이지는 Supabase를 쓰지 않는다(폼 = Resend 메일) (출처: 사용자 결정 2026-11-27 · CLAUDE.md 운영 모델)
⑱ 옛 사이트의 Vimeo 영상은 재생되지 않으므로(8/21 · 11/27 표본 전부 403) 옮길 때 영상 칸을 비우고 제목 · 날짜 · 설교자 · 본문 · 글만 보관한다. `video:`의 Vimeo 지원 코드는 앞으로 새 영상용으로 남긴다 — 재생되지 않는 Vimeo 주소를 콘텐츠에 넣지 않는다 (출처: HANDOFF.md · 사용자 결정 8/21, 11/27)
⑲ 배포는 `vercel --prod --yes --scope onaponds-projects`로만 한다. push로 배포되었다고 보지 않는다 (출처: HANDOFF.md · 배포 방법)
⑳ 커밋 메시지는 `[역할] 작업 내용` 형식 (출처: CLAUDE.md · 핵심 규칙 5)
