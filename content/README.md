# 홈페이지 콘텐츠 작성 안내

이 폴더(`content/`)의 파일을 고치면 홈페이지 내용이 바뀝니다. 콘텐츠를 고칠 때는 이 폴더와 사진만 고치고, 다른 폴더(`src/` 등)는 건드리지 않습니다.

고친 뒤에는 `npm run check:content`(몇 초)로 먼저 검사하고, `npm run build`도 통과해야 합니다. 형식이 틀리면 어느 파일의 어느 항목이 왜 틀렸는지 `파일 → 항목: 설명` 형태의 한국어로 알려 줍니다. 빌드가 멈춘 동안에는 이전 홈페이지가 그대로 보입니다.

**커밋 전 자동 검사**: `npm ci`(또는 `npm install`)를 한 번 실행하면 커밋 직전 검사(`.githooks/pre-commit`)가 켜집니다. `content/`를 고친 커밋은 스테이징한 내용을 먼저 검사하고, 문제가 있으면 커밋을 멈춥니다(예: 공개 동의 없는 연락처). 저장소가 공개라 커밋한 내용은 지워도 기록에 남기 때문입니다. 검사를 건너뛰지 않습니다(`--no-verify` 금지).

## 폴더와 파일

| 위치 | 내용 | 형식 |
|---|---|---|
| `site.yaml` | 교회 이름 · 주소 · 전화 · SNS · 표어 · 예배 시간 | 파일 하나 |
| `history.yaml` | 교회 연혁 | 파일 하나 |
| `staff.yaml` | 교역자 · 직분자 명단 | 파일 하나 |
| `pages/*.yaml` | 페이지별 문구 (홈 · 교회소개 · 공동체 · 새가족 · 예배 안내 · 문의 · 오시는 길 · 목록 머리글) | 정해진 파일만: `home` `about` `community` `visit` `service-times` `contact` `location` `lists` (`.yaml`). 다른 이름의 파일을 두면 오류 |
| `sermons/` | 설교 | 한 편 = `.md` 파일 하나 |
| `praise/` | 찬양 영상 | 한 편 = `.md` 파일 하나 |
| `news/` | 공지 · 소식 · 간증 | 한 건 = `.md` 파일 하나 |
| `bulletins/` | 주보 | 한 호 = `.md` 파일 하나 |
| `albums/` | 갤러리 사진첩 | 한 권 = `.md` 파일 하나 |
| `events/` | 교회 일정 | 한 건 = `.md` 파일 하나 |

- 각 폴더의 `_template.md`를 복사해 새 파일을 만듭니다. 항목 설명은 템플릿 안의 `#` 주석에 있습니다.
- 폴더 이름을 바꾸거나 폴더를 지우면 안 됩니다(빌드가 멈춥니다). 내용이 없으면 폴더를 비워 둡니다.
- `.yaml` · `.md` 파일 안에서 템플릿에 없는 항목 이름을 쓰면(예: `youtube`를 `youtub`로 잘못 씀) 오류가 납니다.
- 필수 항목을 빈칸이나 공백만으로 두면 오류가 납니다. 선택 항목은 줄을 지우면 됩니다.

## 파일 이름

- 영문 소문자 · 숫자 · 하이픈(`-`)만 씁니다. 확장자는 소문자 `.md`입니다. (`.MD` · `.txt` 파일이 폴더에 있으면 오류)
- 파일 이름이 주소가 됩니다. 예: `sermons/2026-11-23.md` → `/sermons/2026-11-23`
- 같은 날 두 편이면 `2026-11-23-2.md`처럼 뒤에 번호를 붙입니다.
- 이름이 `_`로 시작하는 파일은 사이트에 나오지 않습니다(템플릿 · 임시 저장용).

## `.md` 파일의 모양

```
---
title: 제목
date: 2026-11-23
---

여기부터 본문(마크다운)
```

- 파일 첫 줄은 정확히 `---` 세 글자입니다. `---` 뒤에 다른 글자를 붙이면 오류입니다.
- 두 번째 `---` 줄까지가 머리말(항목: 값), 그 아래가 본문입니다.
- 찬양(`praise/`) 본문은 화면에 나오지 않습니다. 본문을 비워 둡니다.

## 날짜와 시간 (한국 시간)

| 쓰는 곳 | 형식 | 예 |
|---|---|---|
| 설교 · 찬양 · 소식 · 주보 · 사진첩 `date` | `YYYY-MM-DD` | `2026-11-23` |
| 일정 `start` · `end` | `YYYY-MM-DD`(종일) 또는 `YYYY-MM-DDTHH:MM` | `2026-12-24T19:30` |
| 연혁 `date` | `YYYY` · `YYYY-MM` · `YYYY-MM-DD` | `1962-08` |

- 모든 시각은 **한국 시간(KST)** 입니다. 24시간제 `00:00`~`23:59`로 씁니다(오후 7시 반 = `19:30`).
- 초(`19:30:00`)나 시간대(`+09:00`, `Z`)는 붙이지 않습니다.
- 달력에 없는 날짜(`2026-02-30`)는 오류입니다.
- 일정의 `end`는 `start`보다 앞설 수 없습니다.

## 자리표시 `{{ }}` (pages/*.yaml)

`pages/` 파일(목록 머리글 `lists.yaml` 포함)의 문구 안에 `{{이름}}`을 쓰면 `site.yaml`(또는 `pages/location.yaml`)의 값으로 바뀝니다. 교회 정보가 바뀌어도 `site.yaml` 한 곳만 고치면 모든 문구가 따라옵니다. 목록에 없는 이름을 쓰거나 값이 비어 있는 항목을 부르면 빌드가 멈춥니다.

`{{`로 시작하는 값은 따옴표로 감쌉니다: `title: "{{vision}}"`. `{{`와 `}}`는 짝으로 씁니다(`{{name}` 처럼 하나가 빠지면 오류).

| 자리표시 | 바뀌는 값 |
|---|---|
| `{{name}}` `{{nameEn}}` | 교회 이름 · 영문 이름 |
| `{{denomination}}` `{{pastor}}` `{{founded}}` | 교단 · 담임목사 · 설립 연도 |
| `{{vision}}` `{{description}}` | 비전 · 교회 소개 한 줄 |
| `{{phone}}` `{{fax}}` `{{email}}` | 전화 · 팩스 · 이메일 |
| `{{address}}` | 도로명 주소 (상세) |
| `{{address.road}}` `{{address.detail}}` | 도로명 주소 · 상세 |
| `{{sns.youtube}}` `{{sns.instagram}}` | 유튜브 · 인스타그램 주소 |
| `{{service.예배id.항목}}` | 예배 정보. 예배 id는 `site.yaml` services의 `id`(sunday · wednesday · friday · dawn …), 항목은 `name` `short` `day` `time` `place` `audience`. 예: `{{service.sunday.time}}` |
| `{{motto.latest.text}}` `{{motto.latest.year}}` `{{motto.latest.keyword}}` | 가장 최근 표어 · 연도 · 키워드 |
| `{{motto.2024}}` | 그 연도의 표어 |
| `{{transport.교통편id}}` | `pages/location.yaml` 교통편 문구. 예: `{{transport.subway}}` (location.yaml 안에서는 못 씀) |

## 사진 · 파일 경로

사진(`image`, `photo`, `cover`, `photos.src`, 소식 `images`)과 주보 `pdf`에는 다음 세 가지만 씁니다.

| 형식 | 예 | 뜻 |
|---|---|---|
| 보관소 경로 | `albums/2026-11-23-sports/001.webp` | 사진 보관소(R2)에 올린 파일 |
| `/`로 시작하는 경로 | `/images/logo.png` | 저장소 `public/` 폴더의 파일 |
| `https://` 주소 | `https://example.com/a.webp` | 외부 https 주소 |

- `http://`, `//`로 시작하는 주소, `..`가 들어간 경로는 쓸 수 없습니다.
- 보관소 경로 · `/` 경로에는 `?` · `#` · `%`를 쓰지 않습니다. 한글 · 공백이 든 파일 이름은 그대로 적습니다(예: `news/예배.webp`).
- 본문 사진(`![설명](경로)`)도 같은 규칙으로 검사합니다. 틀리면 `파일 → 본문 사진 N번째 (경로): 설명`으로 알려 줍니다.
- 주보 `pdf`는 `.pdf`로 끝나야 합니다. 보관소 · `/` 경로의 PDF는 페이지 안에서 미리 보여 주고, 외부 `https://` PDF는 「PDF 열기」 링크만 보여 줍니다.
- 사진첩 사진은 같은 폴더의 `thumb/`에 작은 사진이 함께 있어야 목록이 빠르게 뜹니다(예: `albums/x/thumb/001.webp`).
- 소식 사진에 설명을 붙이려면 `- { src: news/2026-11-23/001.webp, alt: 사진 설명 }`처럼 씁니다. 본문 사진은 `![사진 설명](news/2026-11-23/002.webp)`로 씁니다.
- 유튜브는 `youtube.com` · `youtu.be` 주소를 그대로 붙이거나 영상 ID(11자)만 씁니다.

## 교역자 연락처 (staff.yaml)

- **이 저장소는 공개되어 있습니다.** `staff.yaml`에 적은 내용은 누구나 읽을 수 있고, 나중에 지워도 기록에 남습니다.
- 본인이 홈페이지 공개에 동의한 연락처만 적습니다.
- `email` · `phone`을 적으려면 같은 사람에 `publishContact: true`가 있어야 합니다. 없으면 커밋 전 검사가 커밋을 멈추고, 빌드도 멈춥니다.
- 공개하지 않을 연락처는 이 저장소 어디에도 적지 않습니다.

## 목록의 id

`site.yaml`의 예배 `id`, `pages/community.yaml`의 공동체 `id`, `pages/location.yaml`의 교통편 `id`, 표어 `year`는 같은 목록 안에서 서로 달라야 합니다. 공동체 `id`는 주소(`/community#youth`)가 되고, 바닥글 「공동체」 링크도 이 목록에서 자동으로 만들어집니다.
